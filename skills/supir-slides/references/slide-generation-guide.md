# 幻灯片 AI 生成指南 - `add --instruction` / `insert --instruction`

Agent 在调用 `paipai-slides batch-add`、`add --instruction` 或
`insert --instruction` 前加载此文件，把已锁定的单页内容写成具体、
自包含的 `--instruction`。

多页/复杂规划、逐页 prompt 组装、投研/数据审计、workNN 管理和视觉
QA 按 `SKILL.md` 的参考文档路由读取对应文件；本文件只给最终生成指令
写法。

## 适用范围

本文件仅用于简单单页生成/插入，或在完整流程末端将已锁定的页面规划转换成最终 CLI `--instruction`。

## 默认写法

以下默认值只在用户、已有 PPT 或 `workNN/render_lock.md` 没有更强约束时使用：

- 默认 16:9，除非用户或已有 PPT 指定其他比例。
- 所有专业演示、资料转写、研究分析、业务汇报和模板套用页面，默认优先采用全局内容表达基线：普通内容/分析页使用「顶部结论标题 + 中部观点段或实质 bullet + 底部证据图表/三线表/事实载体」，机制/产业链/路径/因果/竞争格局页使用「顶部结论标题 + 主体视觉推理图」。这条基线优先于模板的卡片化、图标化、dashboard 化表达；只有用户明确要求，或页面角色确实是封面、目录、章节过渡、尾页等特殊页时，才按角色适配。
- 金融/投研/基金产品/机构路演页在没有用户明确特殊风格时，默认采用
  `institutional_research_default`：以 `institutional-research-style.md`
  顶部「风格契约」为权威来源，在 instruction 的 Style constraints 部分写入
  本页适用的短正向风格约束；不要再把同一组风格规则在其他字段反复转述。
- 没有用户模板时，默认仍要使用 skill 内置的 PPTX 截图参考图来稳定生图风格，而不是只靠文字约束。
  参考图位于 `assets/default-template/`，路径相对当前 `paipai-slides` skill 目录解析，调用 CLI 前必须转成绝对路径。按页面角色选择：
  `pptx-slide-01-cover.png`（封面/首页深蓝底白字）、
  `pptx-slide-02-contents.png`（目录页）、
  `pptx-slide-03-section.png`（章节过渡页）、
  `pptx-slide-04-title-page.png`（标题页、普通内容页、结构/机制图页、图表/表格证据页的通用浅蓝渐变参考）。
  调用 `add` / `insert` 时用对应图片作为 `--ref-image`；调用 `batch-add`
  且页面角色不同的时候，用 `--items-json` 为每页设置 `reference_image`
  绝对路径。参考图中的旧标题、旧正文、年份、来源、示例数据只作风格参考，
  不得默认复制到最终页面；最终页面只显示 instruction 指定的真实标题、正文、数据和来源。
  参考图里的 Alpha/PaiWork 标识或页脚水印是内置模板品牌元素，默认应在 instruction 中明确保留；
  如果用户要求去掉品牌、水印、页脚或替换为其他 Logo，应明确要求去除或替换。
- 封面/标题页默认保持克制，不承担摘要页职责：只放主标题、必要副标题、日期、品牌/作者等身份信息和少量背景视觉。不要主动在标题下方加入横向 KPI 指标条、三段大数字、核心观点摘要、证据列表或“量利双升/需求 +260%/利用率 100%”这类摘要模块；这些内容默认放到核心观点页、目录后的摘要页或普通内容页。只有用户明确要求封面展示关键数字/指标摘要，或所用参考模板的封面/标题页本身明确采用这种指标摘要式设计时才加入；模板确实如此时优先参考模板，但仍要避免拥挤和过量指标。
- 标题优先写结论型标题，而不是主题名。
- PPT 主标题、页标题、章节标题末尾不要加中文句号 `。` 或英文 period
  `.`；保留必要的问号、冒号、破折号、括号、数字小数点和英文缩写标点。
- 可见文案直接写结论本身，不在标题、观点段导语、callout、图表注释或总结行中使用
  "关键判断："、"核心结论："、"结论："、"洞察："、"投资启示："、"Takeaway:"、
  "So what:" 等元标签前缀；需要强调时，把后面的结论句加粗、变色或放在显著位置即可。
- 多页 deck 必须保持统一字体/字号层级：同一角色的文字跨页一致（封面标题、章节标题、普通页结论标题、正文/要点、图表轴标签、表格单元格、图注/来源注）。不要让每页自行发明不同字号、字重或字体风格；正文必须在放映尺寸下可读，来源注可更小但仍要清晰。普通内容页不能因为字号过大而牺牲信息量：标题、正文、图标和行距应紧凑克制，优先容纳有事实、因果、约束和证据的观点内容。
- 使用用户模板时，字体不是泛化为"好看的中文字体"：必须按 `render_lock` 的字体签名描述封面/章节标题、正文和注释的风格。如果模板大标题是宋体/楷宋/书法感/高对比衬线标题，Style constraints 要正向要求"高对比中文衬线/宋体或楷宋气质、细横粗竖、优雅笔画、较松字距"，并明确标题不要变成粗黑体、现代无衬线或海报粗字。
- 普通内容/分析/研究页默认采用“顶部结论 + 中部观点 + 底部证据”的结构：
  观点区为 1-3 个自然段（每段 10-20 字加粗导语 + 50-150 字正文）或 2-4 条
  有信息量的 bullet，配 1 个主图/表或 2-3 个并排证据面板。
- 普通内容页的推荐等效字号：普通页标题约 22-26pt（标题很长时继续缩小以避免挤占正文区），正文/要点约 12.5-15pt，图表轴标签和表格单元格约 11-13.5pt，来源注约 8.5-10.5pt。不要把正文放到接近标题的字号，也不要用大图标和大行距把页面撑空；如果内容显得稀薄，应补充事实链或证据载体，而不是放大现有文字。
- 投研/金融页必须先按 `research-to-slide-expression.md` 选择
  `slide_expression_mode`。底稿证据可以完整留在 `workNN/data/registry/`
  和导出 Excel 中；页面只展示 `visible_evidence_ids` 对应的少量证据。
  机制、产业链、供需传导、技术路径、竞争格局、因果链页面优先使用
  `visual_reasoning_page`，不要因为底稿里有很多数据就全部画成图表/表格。
- 如果证据图/表很大，也可采用左侧观点段/要点 + 右侧或下方证据区；
  观点段和 bullet 是普通内容/分析页的关键内容，不要压缩成几个短标签。
- 中部观点段不是装饰文本，而是页面论证的主要承载区；除非用户明确要求极简或页面是纯视觉封面/章节页，不要把段落删成几个 KPI 标签、口号或图标旁短词。
- 概念、关系、替代、产业逻辑、因果链、稀缺度、竞争格局、技术架构类页面可使用机制图/原理图/产业链图，但仍保持扁平克制。
- **用正向描述，少用禁令**：图像模型对“画成什么样”的具体描述远比“不要画什么”
  的否定句敏感，否定句里点名的风格反而可能被画出来。写
  “观点段直接排在白底上，左对齐，无背景无边框”，而不是堆叠
  “不要圆角卡片、不要图标、不要渐变”；所有剩余禁令集中放在 instruction
  末尾 2-3 句以内。
- 写入最终生图 instruction 时，也用正向描述表达文案规则，例如“可见结论以完整句直接呈现，导语为具体业务短语”；不要在 prompt 里反复枚举那些不希望出现的元标签字符串。
- instruction 必须给出页面上需要出现的文字、数据、标签、单位和来源；不要让模型自行补充事实。
- 配色和字体用角色描述，例如“深蓝主色”“橙色强调”“高对比中文衬线标题”“紧凑无衬线正文”；不要要求图片把色号、字体名、提示词或工具说明渲染成可见文字。
- 图表配色要色弱友好；涉及中国市场涨跌时，红色表示上涨/正向，绿色表示下跌/负向。
- 生成地图页时尤其谨慎。涉及中国领土、行政区、区域市场、门店/产能/产业链地理分布等地图表达时，Style constraints 或 Suggested visual 必须明确：采用符合中国政治正确的中国地图，台湾是中国地图的一部分，藏南地区属于中国且不使用麦克马洪线作为中国边界，南沙群岛属于中国并应包含在南海诸岛表达中。若无法保证边界和岛屿正确，不要生成具体国界/疆界地图，改用抽象区域示意、业务分布矩阵、流向图或不含边界争议的定位示意。

金融/研究型页面的详细风格、palette、混合渲染和确定性覆盖规则，以 `image-renderer.md` 与 `workNN/render_lock.md` 为准。

## instruction 结构

每条 instruction 只描述一张幻灯片，并且必须具体、自包含。没有用户或工作底稿支持的信息不要写成事实。

```text
生成一张16:9专业演示幻灯片图片。

Slide type: <封面/目录/内容页/数据分析/对比/流程/总结>

Expression mode:
<投研/金融页必须填写：visual_reasoning_page / evidence_page / summary_page / appendix_data_page / transition_page。说明本页为什么选择该模式；registry 中的 archive evidence 不需要全部显示。>

Style preset:
<默认采用全局内容表达基线；金融/投研/基金产品/机构路演页采用 institutional_research_default。说明本页是普通内容/研究页、证据页、还是封面/目录/章节/机制/原理/产业链等角色例外。用户模板只覆盖视觉皮肤，除非用户明确要求沿用其内容表达。>

Main title:
"<结论型标题>"

Subtitle:
"<副标题或日期，可省略>"

Identity / attribution:
<作者/制作者、受众/收件方、模板品牌、来源 provider 分开写。无法确认作者或制作者时，明确写“不显示作者/机构署名”；不要把受众写成作者、研究部或资料来源。>

Dominant visual argument:
<visual_reasoning_page 写替代关系拓扑、稀缺度坐标、产业逻辑对比、价值链图、供需传导图、因果链、2x2 矩阵、时间线拐点图等。evidence_page 写本页主证据载体：折线/柱状/表格/截图/产品目录/三线表等，以及它如何支撑标题结论。说明主要节点、方向、坐标轴、分组和视觉重心。>

Content blocks:
<普通内容/研究页写 1-3 个自然段，每段给出 10-20 字加粗导语 + 50-150 字正文，全区合计不超过约 350 字；也可写 2-4 条每条 40-110 字的 substantive bullet。中段文字要保留原因、事实、影响或约束，不压缩成短标签。机制图页面才把正文收敛为支撑图解的短标签、关键数字和必要注释。>

Visible wording:
<页面上只显示最终标题、正文、图表标签和来源；本 instruction 的字段名、内部分类名和元标签不渲染到页面。所有结论/callout 直接写结论句，导语使用具体业务短语。>
<主标题、页标题、章节标题末尾不加中文句号或英文 period。>

Data / chart / table details:
<只写本页可见证据。evidence_page 如有数据支撑，选择折线图、柱状图、堆叠柱、瀑布图、散点/气泡图、饼/环图或精简表格；写明完整可见数据、单位、坐标轴、图例和来源 provider。visual_reasoning_page 默认只写 0-3 个关键数字或短 callout，其余数据留在 workpaper registry / appendix / Excel。>

Workpaper evidence:
<列出内部证据链接但明确不渲染这些 ID：claim_id、visible_evidence_ids、archive_evidence_ids、source_ids。说明 archive evidence 仅用于事实约束，不要把 registry ID、工具名、查询语句或全部底稿数据画到页面上。>

Visible evidence budget:
<主叙事页默认 0-5 个可见数字、一个主视觉论证、最多一个主图/表或两个紧凑证据面板；appendix_data_page 例外。>

Investment evidence archetype:
<投研/买方决策页可选：evidence_triptych、claim_then_artifact、thesis_left_table_right、small_multiples_comparison、chart_table_crosscheck、scenario_monitor_panel。说明 claim zone、evidence zone 和 decision/monitoring implication 如何分配。非投研页可省略。>

Suggested visual:
<visual_reasoning_page：顶部 15-20% 放结论型标题，主体 60% 以上放机制图/产业链图/路径图/因果链/矩阵/地图，少量 callout 解释关键节点。evidence_page：顶部 15-20% 放结论型标题和必要的一条直接结论句，中部/左侧观点阐述，底部或右侧 45-60% 放 1 个主图/表或 2 个紧凑证据面板。封面/标题页/目录/章节/尾页按角色适配；封面/标题页默认不加入 KPI 指标条、三段大数字、证据摘要或核心观点列表，除非用户明确要求，或参考模板封面本身就是这种指标摘要式设计。>

Frame / icon policy:
<开放式网格/细线/三线表/分区标题；观点段和 bullet 默认不加外框。避免大量圆角框。普通内容/研究页图标 0-1 个；机制图可少量使用克制线性图标。用户模板中的卡片/图标只有在真实表达分组、流程、表格、机制节点或用户明确要求时才沿用。>

Visible source note:
<仅研报/投研报告/用户要求/模板要求时显示。优先写可确认的最原始来源，如“资料来源：中指院，招商证券整理”或“资料来源：公司公告，Bloomberg”；非研报型页面默认不显示来源，但内部仍保留数据审计。若数据来自 Alpha派 / PaiWork 平台数据库或检索工具，先检查 registry/data_audit 中是否有原始发布方；找不到更具体源头，或 data_analyst/doc_searcher/search_paipai/结构化数据库产出为平台综合结果且无具体来源时，页脚写“资料来源：Alpha派”。不要写“Alpha派数据库”“PaiWork数据库”“内部数据库”或具体工具名。>

Style constraints:
<专业/研究/业务汇报页：先写明全局内容表达基线优先生效。金融/投研页按 institutional-research-style.md 顶部「风格契约」执行，只写本页需要的短正向风格约束和特有约束（如参考图需保留/排除的元素），不要整段堆叠重复禁令。同时写明使用 render_lock 中统一字体/字号层级：同角色文字跨页一致，普通内容页标题/正文/图表标签/表格/来源注层级稳定且紧凑，不能用过大字号、图标或行距牺牲信息密度。非投研页：用正向描述写明目标形态，并保持结论标题、中段观点、证据载体、少卡片少图标、非 dashboard/非营销海报的默认约束；剩余禁令收敛在末尾 2-3 句。>
```

## 页面要点

| 页面类型    | 必须说明                                                       |
| ----------- | -------------------------------------------------------------- |
| 封面/标题页 | 标题、副标题、日期、可见作者/制作者策略、受众/内部场景（如有）；默认不放 KPI 条、三段大数字或核心观点摘要；若模板封面明确采用指标摘要式设计，可按模板保留 |
| 内容/分析   | 结论型标题、2-4 个内容块、关键数字                             |
| 数据图表    | 图表类型、完整数据、单位、坐标轴、图例、来源、直接含义句       |
| 对比分析    | 对比维度、各项数值、差异高亮                                   |
| 流程/结构   | 节点名称、层级、流向、分组关系                                 |
| 关系/替代   | 节点、方向、强弱、替代/互补/约束关系、直接结论                 |
| 稀缺度/定位 | 坐标轴含义、各对象位置、分区标签、箭头方向、结论短句           |
| 产业逻辑    | 左右或上下对比对象、核心差异维度、图标/模块、最终判断          |
| 总结        | 直接结论、建议/后续动作/风险                                   |

## 批量生成

提交 `batch-add` 前，先形成逐页清单，再把每一页转换成一条完整 `--instruction`。

- 按 `SKILL.md` 的 `batch-add` 拆批规则提交：≤30 页一批；31-80 页按每批接近 30 页拆分，批次之间串行等待；用默认并发、不传 `--concurrency`。
- 每页至少明确：页面角色、结论型标题、正文内容、数据/来源（如有）、视觉建议、风格约束。
- 逐页清单里的 `title` 和 instruction 中的主标题都不要以中文句号 `。`
  或英文 period `.` 结尾；正文句子、数字小数点和英文缩写不受此限制。
- 每页默认先套用全局内容表达基线：普通内容/分析页要有结论标题、中部观点段或实质 bullet、底部/右侧证据载体；机制、产业链、供需传导、技术路径、竞争格局、因果链页要有结论标题和主体视觉推理图。封面、目录、章节过渡、尾页按角色例外。
- 封面/标题页不是摘要页：除非用户明确要求，或参考模板封面本身明确采用指标摘要式标题页设计，不能把核心观点、关键数字、KPI 三栏、证据结论或大数字指标条塞到标题页。需要突出关键数字时，优先单独规划 `summary_page` / 核心观点页；模板已经这样设计时可保留，但不要额外增加更多指标。
- 投研 / 金融 / 公司 / 行业 / 宏观类页面在写每条 instruction 前，先确认该页所需事实已经经过 `data-acquisition.md` 的页面级证据补全：可量化内容有结构化数据或 chart/table spec，定性判断有 `search_paipai` / `doc_searcher` / 公告 / 研报 / 路演纪要等来源支撑，关键反证或低置信点已进入 `argument_map`。同时确认该页在 `page_evidence_registry.jsonl` 中有 `claim_id`、`visible_evidence_ids`、`archive_evidence_ids` 和适用的 `source_id` 链接；只有涉及结构化数据、图表、表格或可见关键数字时才要求 `dataset_id` / `figure_id` / `table_id`，否则用来源记录、claim 记录和 archive evidence 支撑。无法取得证据时明确 `Needs-Source` 处理。缺证据时不要把模型常识写成页面事实，但也不要把 archive evidence 全部画到页面上。
- 主叙事页必须遵守 visible evidence budget：默认 0-5 个可见数字、一个主视觉论证、最多一个主图/表或两个紧凑证据面板；多余证据进入底稿、Excel 或 appendix。
- 对解释型页面，先选择视觉表达模型，再写文字。若页面出现 4 个以上内容块、每块超过 2 行，优先改写成拓扑图、坐标轴、流程、2x2、对比画布或价值链图。
- 对数据支撑页面，先选择图表或表格表达：趋势用折线，比较/排行用柱状，结构占比用饼/环图，拆解用瀑布/堆叠柱，精确假设和同业对比用表格或三线表。
- 对投研/买方决策页，可以采用投资证据页原型：`evidence_triptych`（顶部结论 + 下方三证据）、`claim_then_artifact`（简短判断 + 截图/产品目录/渠道证据）、`thesis_left_table_right`（左观点+图，右大表）、`small_multiples_comparison`（国内/海外/全球或多情景小多图）、`chart_table_crosscheck`（图表与表格交叉验证）、`scenario_monitor_panel`（情景/触发条件/跟踪指标）。这些页面可以更密，但必须让每个图表/表格回答一个明确的投资决策问题。不要把这些 evidence archetype 用在所有页面；结构性主题优先用 visual reasoning patterns。
- 每条 instruction 必须能独立生成该页，不依赖“同上”“继续上一页”“沿用前页”等上下文。
- 多页共享的 master、配色、页脚、来源规则写进每条 instruction，或在多页/复杂流程中写入 `workNN/render_lock.md` 后按其组装。
- 多页共享的字体/字号层级也必须写进 `workNN/render_lock.md` 并在每条 instruction 中遵守；若使用用户模板，则先从模板 OOXML/代表页提取标题、正文、图表标签、表格、来源注的字体签名和相对字号层级，不能提取时回落到默认紧凑无衬线层级。封面/章节页有独特展示字体时，逐条 instruction 必须重复该展示字体签名，不能只依赖参考图。
- 内容页遇到“字大、图标大、信息少”的风险时，优先压缩字号/行距/图标尺寸并恢复观点内容或证据区；不要为了让页面看起来更干净，把 2-4 条实质判断删成几条短标签。
- 使用 `institutional_research_default` 且没有用户模板时，多页共享的默认参考图映射也必须写进 `workNN/render_lock.md`：cover → `assets/default-template/pptx-slide-01-cover.png`，toc → `assets/default-template/pptx-slide-02-contents.png`，section → `assets/default-template/pptx-slide-03-section.png`，title page / ordinary content / diagram / chart-table evidence → `assets/default-template/pptx-slide-04-title-page.png`。生成时按页面角色传入对应 `reference_image`，不要把 overview 或任意单张图全局套用到所有页面。
- 每条 instruction 必须遵守统一 master/logo/footer/source 规则；不要生成页码——带参考图时参考图里的页码默认会被照搬，必须在 instruction 里显式排除（如"不要保留参考图右下角的页码"）。元素不得重叠或遮挡。
- 每条 instruction 必须遵守身份策略：作者/制作者、受众/收件方、模板品牌、资料来源分开处理；不确定作者时隐藏作者署名。
- 内部页 ID（如 P01）只用于规划、文件名或底稿引用，不写入可见页面内容。
- 逐页检查可见文案：字段名、内部分类名和"关键判断/核心结论/结论/洞察/投资启示/So what/Takeaway"这类元标签不进入画面；结论区直接显示结论句。
- 逐页检查标题标点：主标题、页标题、章节标题末尾不带句号。
- 有逐页 `title`、`layout` 或不同参考图时，优先使用 `batch-add --items-json`。

## 约束

- 一条 `add` / `insert` instruction 只描述一张幻灯片。
- 图片中的文字以中文为主，必要的金融/技术缩写可以保留英文。
- 普通内容/分析/研究页观点区为 1-3 个自然段（每段 10-20 字加粗导语 +
  50-150 字正文，全区合计不超过约 350 字），或 2-4 条每条 40-110 字的
  bullet。不要为了视觉简洁删掉必要解释，不要把观点压缩成几个短标签。
  超出 350 字、含精确数值表格、或图表需保留超过约 10 个精确数据标签时，
  必须按 `image-renderer.md` 的硬规则走确定性覆盖/混合渲染。
- 普通内容页的信息密度优先于大字展示感。除封面/章节/转场页外，避免接近海报式的大标题、大正文、大图标列表；若页面只剩 3 条短句，应补充每条的业务原因、数据、时间、单位、影响或约束，或加入小型证据表/图。
- 机制图、原理图、产业链图、流程图页面正文更克制：每个视觉节点使用短标签 + 最多一行解释。
- 封面/标题页正文更克制：不要默认添加横向指标栏、大数字组、摘要卡片或证据结论列表；这类内容属于摘要/核心观点/内容页。若用户模板封面已明确使用这种模块，按模板保留其位置、比例和数量，不再额外扩展。
- 投研密集页放宽文字量时，必须采用“结论标题 + 1-3 条实质判断/假设 + 证据区 + 决策或跟踪含义”的结构；可见文本直接写判断内容，不用“判断：”“关键判断：”作前缀；不要把长段落铺满整页。每个证据区都要有图/表/截图/产品目录/监控指标等明确载体。
- 禁止把普通内容/分析/研究页做成科技发布会、咨询信息图、SaaS dashboard、数据大屏或营销海报；除非用户明确要求，不使用深色霓虹、科技光效、玻璃拟态、3D、发光数字或电影感背景。
- 段落文字不要加外框；只有当边框表达真实分组、表格、流程阶段、图例或对比关系时才使用。
- 不要因为页面有 2-4 条事实型 bullet 就强行改成机制图；只有解释
  机制、传导、替代、产业链或架构关系时才使用图解化表达。
- 图表/表格必须提供准确数据、标签、单位和来源；投研/金融页的数据、图表、表格和来源必须来自 `workNN/data/registry/` 中已登记的 source/dataset/figure/table 记录或用户材料；不要让模型发明数字或来源。Registry 中的证据不等于都要可见，只有 `visible_evidence_ids` 进入页面。
- 可见来源默认只在研报/投研报告、用户明确要求、或模板已有来源区时出现；来源文字保持简洁，优先写最原始的可确认来源，不写长报告标题、URL、检索说明或过细出处。若数据经二级资料转引，采用“原始来源，整理/转引方整理”的短写法，例如“资料来源：中指院，招商证券整理”。详细来源链放在 `workNN/data_audit.md`。
- 涉及 Alpha派 / PaiWork 平台数据库、结构化数据、`search_paipai`、`doc_searcher`、`data_analyst` 或同类平台检索时，不要默认把 Alpha派当作原始来源；先查看 `source_registry.jsonl` / `data_audit.md` / 原始工具输出是否标明公告、统计局、交易所、公司、行业协会、第三方数据机构等源头。只有源头不可识别，或平台工具返回的是无具体出处的平台综合/加工数据时，才可见归一为“Alpha派”。不要在页面中写“Alpha派数据库”“PaiWork数据库”“平台数据库”“内部数据库”或工具名。详细数据库、工具、文档类型和检索记录只写进 `workNN/data_audit.md`。
- 不要把受众或委托方误写成作者、研究部或资料来源。比如“给嘉实基金内部使用/向嘉实基金汇报”只说明受众或使用场景；除非用户明确说明，否则不要写“作者：嘉实基金”“资料来源：嘉实基金研究部”。
- 不要在可见页面中出现内部 ID、私有来源标签、设计说明、提示词规则、工具说明，或“关键判断/核心结论/So what”等元标签。
- 用户参考稿/品牌稿中的公司名、Logo、页脚声明必须先经 `identity_context` 判定角色；明显位于封面、页眉、页脚、母版固定区并承担模板品牌识别的 Logo 默认保留（精确拼写），用户要求去除或替换时覆盖默认。禁止无中生有的 logo、作者、部门和来源。
- 涉及中国地图或中国区域地理表达时，必须检查政治正确边界：台湾属于中国地图一部分；藏南地区属于中国，不按麦克马洪线切出中国边界；南沙群岛属于中国。无法可靠呈现时，改用抽象区域图或非边界地图表达。
- CLI 调用、异步等待和批量生成命令以 `SKILL.md` / `image-renderer.md` 为准；`task --wait` 返回后必须检查生成结果。
- 多页/复杂 PPT 按 `visual-qa.md` 做 QA。

## 反面模式

| 错误做法                                                                | 问题                                   | 正确做法                                                                                  |
| ----------------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------- |
| `做个好看的封面`                                                        | 过于模糊                               | 提供标题、副标题、日期、机构                                                              |
| `画个图表`                                                              | 没有数据                               | 提供数据系列、标签、单位、来源                                                            |
| `列出六类产品，每类写概念/应用/急缺`                                    | 容易变成文字堆叠                       | 改成“核心品类分组 + 替代关系拓扑 + 稀缺度坐标”，只保留短标签和直接结论                    |
| `做一页对比 MLCC 和存储`                                                | 容易变成上下两栏文字表                 | 改成“产业逻辑对比图”，用市场规模、扩产弹性、技术壁垒、护城河四条横向视觉泳道表达          |
| `每块内容放在圆角框里并配图标`                                          | 页面显得模板化、割裂                   | 用开放式网格、细分隔线和少量语义图标；图标只标关键分区                                    |
| `做成科技感信息图/数据大屏风格`                                         | AI 感重，降低机构可信度                | 按 institutional-research-style.md 的风格契约写短正向约束：白底研报页、观点+证据、朴素图表/表格 |
| `在 instruction 里堆叠十几条"不要…"禁令`                                | 否定句对图像模型弱，点名风格反而被画出 | 用正向描述写目标形态；剩余禁令收敛到末尾 2-3 句                                           |
| `为了简洁，只保留几个短标签`                                            | 观点像口号，缺少审阅信息               | 保留中等长度 bullet，写清原因、数据、影响、约束条件                                       |
| `左侧观点段也套一个醒目的圆角外框`                                      | 观点区像模板卡片，AI 感强              | 观点段用留白、缩进、字号、粗体和细分隔线组织；只有真实分组才加轻边框                      |

| `资料来源：Alpha派数据库 / 内部数据库 / search_paipai`                  | 暴露内部库或工具名，或把检索渠道当源头 | 若可识别原始来源则写原始来源；不可识别或平台综合结果才写“资料来源：Alpha派”                |
