# 幻灯片 AI 编辑指南 - `update --instruction` / `batch-update`

Agent 在调用 `paipai-slides update --instruction` 或 `batch-update` 前加载此文件，把用户意图写成具体、可定位、带保留约束的编辑指令。

本文件只负责简单编辑和最终 CLI instruction 写法。复杂 bbox 编辑、反复局部编辑、完整 QA 修复要同时读取 `bbox-editing.md`；完整 QA 读取 `visual-qa.md`。

## 核心原则

编辑指令必须具体。每条指令尽量包含：

1. 要修改的元素：标题、数据标签、图表系列、注释、配色、局部版面等
2. 当前内容：页面上现在是什么，帮助模型定位
3. 目标内容：要改成什么，给出准确文字、数字或颜色角色
4. 保留约束：哪些内容、布局、来源、页脚、logo 必须不变

除非用户明确要求其他表达方式，涉及整页重做、局部风格修复、布局优化、模板套用后的返工、或 QA 发现页面卡片化/图标化/AI 感过重时，编辑目标默认回到全局内容表达基线：普通内容/分析页保持顶部结论标题、中部观点段或实质 bullet、底部/右侧证据图表/三线表/事实载体；保留中部观点文字的信息量，不把它压缩成短标签；少卡片、少图标，不改成科技发布会、咨询信息图、SaaS dashboard、数据大屏或营销海报。

当用户指出内容页“字体太大、信息量太少、太空、只有几条短句”时，按信息密度修复而不是只做视觉缩放：降低普通页标题、正文、图标和行距到紧凑但清晰的层级（正文约 12.5-15pt 等效，图表/表格约 11-13.5pt，来源注约 8.5-10.5pt），恢复 1-3 个中等观点段或 2-4 条有事实/因果/约束/影响的 substantive bullet，并在需要时补充小型图表、表格或证据载体。不要把正文做成接近标题的大字列表。

当用户指出封面/标题页“拥挤、指标太多、像摘要页”时，先判断当前参考模板是否明确采用这种指标摘要式封面。如果模板本身就是这种风格，优先保留模板语言，只减少拥挤度、指标数量或字号；如果不是模板明确风格，则默认删除或迁移 KPI 指标条、三段大数字、核心观点摘要、证据结论列表等内容，只保留主标题、必要副标题/日期、品牌/作者等身份信息和克制背景；若这些指标仍有价值，建议移到单独的核心观点页/摘要页。

## Instruction 写法

编辑指令优先写成“当前内容 -> 目标内容 -> 保留约束”的形式：

```bash
paipai-slides update <file> --slide-id <SID> \
  --instruction "将标题从'2023年Q3营收对比'修改为'2024年Q3营收对比'，保持标题位置、字号和其他内容不变。"
```

常见写法：

- 文字修正：`将标题从'旧标题'改为'新标题'，保持标题位置、字号和其他内容不变。`
- 数据标签更新：`将第三个柱子的数据标签从'89亿'更新为'92亿'，其他柱体、坐标轴、图例和来源不变。`
- 样式调整：`将蓝色柱体调整为更深的蓝色，保持数据、标签、图例和版式不变。`
- 局部版面：`只调整左上角摘要模块的间距和对齐，保留其他模块、页脚和 logo 不变。`
- 信息密度修复：`将本页从大字号短句列表改为紧凑研究内容页：缩小标题、正文、图标和行距，保留现有三家公司主线，但把每家公司扩展为有事实、数据、业务含义和约束的 2-3 行说明；正文保持清晰可读，不要改成海报式大字。`
- 标题页去拥挤：`如果参考模板封面本身不是指标摘要式设计，将封面标题下方的大数字/KPI 指标条移除，只保留主标题、副标题、日期、品牌标识和克制背景；如果模板封面明确采用指标摘要式设计，则保留该设计语言但减少指标数量和拥挤度。`

按 `SKILL.md` 的异步任务规则，在提交后使用 `task --wait` 等待；返回 `done` 后从其 JSON 取 `filePath`（新图路径）并 `read_media` **这个返回的路径**核对——绝不复用旧路径、绝不按 `{slide_id}-1.png` 猜（旧路径是改前的图）。

## 合并多处修改

同一张幻灯片上的多个小修改，尽量合并到一条 `update` 指令中：

```text
1. 将标题从'2023年收入分析'改为'2024年收入分析'。
2. 将第二个柱子的数据标签从'81亿'更新为'85亿'。
3. 将底部来源从'旧来源'改为'公司公告'。
保持页面布局、图表类型、页脚位置和其他数据不变。
```

## 批量编辑

一次修改多张幻灯片时，先形成逐项编辑清单，再提交 `batch-update --items-json`。

- **一次性把所有要改的页放进同一条 `batch-update`**，用默认并发、不传 `--concurrency`；拆批规则见 `SKILL.md` 的 batch-update 一节。
- 每项必须包含：`slideId`、要修改的元素、当前内容、目标内容、保留约束。
- 同一张幻灯片上的多个小修改合并到同一个 item；不要为同一页连续发多个 item。
- 每项 instruction 必须自包含，不要写“同上”“按前一页处理”。
- 涉及框选时先读 `bbox-editing.md`，标注并理解区域后，只在 item instruction 中写空间语义修改，不手写或传入坐标。
- 任务完成后逐项检查（对着 `task` 返回的最新 `filePath`/`changedPaths` 那批新图）：目标页是否修改成功、未涉及区域是否保持不变、数据/来源是否一致。看不到变化先确认读的是新图（旧路径会显示改前的图），别急着返工。

## Region 编辑

用户在前端框选区域时，先读取 `bbox-editing.md`，并用 `annotate-region` 查看标注图后再写 instruction。

- Agent 不要手写、猜测或传入坐标。
- `--instruction` 按元素在页面里的**内容和空间位置**点名它（例如“标题下方、饼图右侧的说明文字”），描述要做的修改。
- 位置要写清楚（标题下方、饼图右侧…）：位置越准，编辑越能精确命中要改的元素。
- **严禁在 instruction 里写“红框/标注/框选/选中区域”**：红框只画在给 Agent 定位的标注图上，编辑模型基于无框原图工作、看不到任何框。看完标注图先把“红框内的 X”翻译成 X 的内容+位置描述再下笔——指令其余部分再具体，只要出现“红框”就会误导模型。
- 按 `SKILL.md` 使用 `2>&1` 检查框选是否命中；未命中时不要声称完成了框选编辑。

复杂 bbox、复杂页面或多轮局部修复，读取 `bbox-editing.md`，并按该文档要求记录到当前 `workNN/edits/`。简单一次性编辑不创建 `workNN/`。

## 编辑前准备

有编辑器上下文时，直接使用上下文中的 presentation path 和 `slide_id`。

无编辑器上下文时，先用 `paipai-slides show <file>` 查询当前状态，确认目标 slide 后再编辑。

## 何时不要编辑

以下情况优先重新生成页面，而不是继续局部编辑：

- 内容主题完全替换
- 页面整体布局大幅变化
- 修改范围影响大半个页面
- 多次编辑后可读性下降
- 用户明确要求重做页面

重生成计入同页 2 轮自发返工预算（见 `visual-qa.md`「同页返工上限」）：第 1 轮修复把页面改劣化时，第 2 轮直接重生成而非继续修补（先 `unset PAIPAI_SLIDES_REGIONS_JSON_B64` 清掉残留框选，再按整页完整规格重述）。

## 约束

- `update --instruction` 每次只编辑一张幻灯片。
- 一次要编辑多张幻灯片时用 `batch-update`，不要循环发多个 `update`。
- 风格或布局类编辑默认保持全局内容表达基线；用户没有明确要求时，不新增圆角卡片网格、图标逐条 bullet、dashboard 面板、营销海报式大字和装饰光效。
- 除非用户明确要求，否则保留页面布局、来源、logo 和无关文字；不要新增页码，已有页码仅在用户明确要求时保留（模板/参考图带页码不算要求）。
- 没有准确替换值或工作底稿支持时，不要修改数字、标签和来源。
- 提交后必须按 `SKILL.md` 的异步任务规则等待任务完成。
- 完成后只检查被改动的页：编辑区域、边界、未选中区域、文字可读性、数据和来源一致性；不要整本重看。多页/复杂 PPT 或完整 QA 任务按 `visual-qa.md` 写入 `workNN/visual_qa.md`。
